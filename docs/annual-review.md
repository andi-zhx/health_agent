## Windows 体验入口

完整解压项目，安装 64 位 Python 3.10–3.14（推荐 3.12），双击 **启动演示系统.bat**。首次需要联网安装依赖，之后自动打开 `http://127.0.0.1:5050`。

默认账号 `admin`，密码 `123456`。演示库单独保存在 `demo_data/medical_system.db`，不会覆盖项目原有的数据库。再次启动沿用你的演示修改，不会重复导入或重置。正式业务仍使用 **启动医疗系统.bat**（默认 5000 端口）。

手动运行演示环境：

```bash
python seed_demo_data.py
# Windows PowerShell
$env:HEALTH_AGENT_DATA_DIR = "$PWD\demo_data"
.venv\Scripts\python.exe launch.py --port 5050
# macOS / Linux
HEALTH_AGENT_DATA_DIR=./demo_data .venv/bin/python launch.py --port 5050
```

如要重新体验初始案例，先关闭演示服务，将 `demo_data` 文件夹改名备份，然后再双击演示入口。脚本发现已有非演示库会拒绝导入，发现已有演示库会保留原状。不要用旧的 `seed_sample_data.py` 替代此入口；旧脚本的重建行为不同。

## 建议演示顺序

1. **年度总览**：选择 2026 年，介绍建档覆盖、现场与上门服务、反馈覆盖和自述改善。再展示四类设备、月度服务、健康关注分组与疾病记录分布。
2. **体验与回访**：点击设备的“查看反馈”，按项目、姓名或回访状态筛选。打开一条记录查看同一维度的体验前后困扰评分、满意度、不适表现及回访结果。
3. **登记与回访**：登记体验，成对填写 0–10 分；如有不适，补充处理情况。待回访记录可填写实际回访时间与结果，保存后统计会更新。已有预约优先从原“理疗记录 → 待填写”入口关联登记。
4. **健康档案 / 健康画像**：查看单人档案和整体分布。原工作台、客户、预约、上门服务、理疗记录附件、查询导出、设备和审计入口均保留。
5. **年度报告**：从总览打开报告，点击“打印 / 保存 PDF”；将纸张设为 A4，可开启背景图形、关闭浏览器页眉页脚。总览“导出数据”可下载含六个工作表的 Excel。

## 100 个虚构案例的构成

| 内容 | 数量 |
| --- | ---: |
| 虚构干部档案（演示干部001–100） | 100 人 |
| 健康评估（每人两次） | 200 份 |
| 健康记录摘要 | 100 份 |
| 四类现场设备服务及签到 | 300 次 |
| 上门服务 | 20 次 |
| 体验反馈 | 310 条 |
| 故意保留待补录反馈的服务 | 10 次 |

案例文件为 `demo/cases-2026.json`，生成规则在 `demo/generate_cases.py`；固定截止日 2026-11-24。包含不同年龄、病史组合、服务项目，以及改善、无改善、加重、已回访和待回访等状态，以便体验完整流程。姓名、身份证、电话、地址及健康信息均为虚构，不得拨打样例电话或用于身份验证。

初始演示统计：完成服务 320 人次，关联反馈 310 次，覆盖率 96.9%；有效改善反馈 310 条，其中本人自述明显或部分改善 195 条，占 62.9%。这些数字用于检验软件功能，**不能用于证明真实年度业绩或医学疗效**。

## 指标与建议如何产生

- 完成服务按状态为 `completed` 的预约计数，一条预约一次；未完成、已取消、未来记录不纳入。
- 关联反馈要求客户、预约类型和预约 ID 一致；一项服务重复反馈只取最新一条，手工无预约反馈不会抬高服务反馈覆盖率。
- 自述改善比例 =（明显改善 + 部分改善）/（明显改善 + 部分改善 + 无改善 + 加重）。空分母显示“—”。
- 体验评分在同一维度下由本人评价困扰程度，0 为无困扰，10 为非常困扰。未记录不会当作零分。满意度为 1–5 分，单独统计。
- 健康状况使用截止日之前每人的最新评估。病史按明确填写的标签统计，可多标签归类，不从检测值推断诊断。“无”是明确记录；“不详”、空白等不会被解释为无疾病。
- 重点关注用于服务管理：多项病史或监测异常优先关注；其他已记录问题进入常规随访；资料不足单列。它不是临床风险评分。
- 过去年度的回访完成数以实际完成时间不晚于该年截止日为准。历史档案以当前数据库保存内容回看，不是不可变的年末快照；后续修订及删除可能改变历史汇总。
- 设备数量显示当前配置，不能解释为全年建设数量。服务次数没有可用时长分母，不称为“设备利用率”。
- 运营建议根据缺失反馈、待回访、不适、病史需求及服务量给出登记、复核、宣教和排班方向；不自动推荐设备治疗，不将主观改善解释为因果疗效。

## 年终报告可采用的建设表述

> 本年度完善了军休健康服务的信息化管理能力，形成“干部建档—健康评估—现场及上门服务—体验反馈—持续回访”的记录流程。系统新增年度总览，汇集服务建设、健康画像和改善反馈，支持艾灸机器人、高压氧舱、听力检测、按摩机器人等现场项目登记；通过回访任务、异常体验复核及统计导出，为服务安排和运营改进提供依据。

以上是软件能力表述。正式报告中的人数、人次、改善比例和建设完成日期，需要使用经核实的实际业务数据。系统演示截图应保留“虚构演示数据”标记。

## 升级与验证

升级前备份原数据库、附件目录和 `.secret_key`；不要用 ZIP 内同名数据库覆盖自己的业务库。新字段为增量迁移，启动不清理旧设备、满意度及设备使用历史表。报告和新接口沿用现有登录校验。

回归测试：`python -m unittest discover -s tests -v`。测试在临时数据目录运行，覆盖 Windows 启动、旧库迁移、数据保留、统计分母、评分校验、回访更新、报表与演示导入保护。
