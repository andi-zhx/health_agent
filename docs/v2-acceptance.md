# V2 升级、统计口径及验收说明

> 2026-11-26 最新更新：品牌为“静安军休所”，原综合驾驶舱与群体画像合并为“主页”，导航共六个主模块；移除专业管理分层、慢病共存和病史共存矩阵展示，小字放大并改黑。按用户后续明确要求，下载包默认库已替换为 **300 位完整虚构案例**，覆盖原数据；年龄性别仅显示五个给定年龄组及男/女。“保留旧库升级”与“覆盖为案例”是两种不同操作，下面分别说明。

实现依据：2026-11-25《军休所智慧康养信息化系统优化方案 V2》。附件里的 29 人、病史记录数及图示比例仅用于说明需求，没有写入正式经营数据。原有档案、预约、附件、导出、备份、审计入口保留为辅助工具；按本次附件移除独立群体指标监测导航、群体医学均值和无关正式项目。

## 一、首次使用、覆盖案例及保留旧库升级

下载本版后直接双击 `启动医疗系统.bat`，默认库已填充 300 位案例；账号 `admin / 123456`。已有安装要按本次要求覆盖旧数据：关闭系统、更新代码、双击 `覆盖为300条案例并启动.bat`。脚本先完整构建并校验新库，再备份实际旧库至 `database_backups/before_300_cases_*.db`，最后替换活动数据库。旧业务和账号不混入新案例，原附件文件不被删除；普通启动不会重复重置数据。

以下步骤仅用于**选择保留原有业务数据**的升级方式：

1. 关闭正在运行的系统，另存一份**完整旧项目目录**，包含 `medical_system.db`、`.secret_key`、`uploads/`、附件、已有备份及个人设置。
2. 将新代码解压到新目录。保留下载包和旧库分开，不把下载包内的数据库覆盖旧数据。推荐将工作数据单独放到 `D:\health_agent_data`，把旧数据及附件复制到该目录。
3. 在 Windows CMD 执行 `set HEALTH_AGENT_DATA_DIR=D:\health_agent_data`，再 `call start.bat`。也可在新代码目录放入旧库及原附件目录后直接双击启动。
4. 首次 V2 启动会在**实际数据目录**下生成 `database_backups/before_care_v2_*.db`，早于旧版初始化和 V2 迁移。自动备份失败则停止升级。新空目录没有旧库，不需要迁移前备份。
5. 管理员登录后到“管理设置 → 查看迁移与项目核验”，检查数量、备份路径和待核验名称。再确认实际设备资产、人员、专业参考范围和账号授权。

正式模式沿用原管理员账号密码。新建库默认 `admin / 123456`；本地默认仅监听 `127.0.0.1`。正式环境不自动创建演示用户或干部，也不虚构设备资产。原系统已有的设备、人员记录按原数据保留。

### Windows 启动修复

安装器创建本项目 `.venv`，用同一个解释器安装并运行，支持 Python 3.10–3.14；固定可用依赖，补充 Windows 时区数据，处理中文路径和传统控制台编码。密钥本机生成并持久化；启动先确认 `/api/health` 就绪，端口被占用时明确提示。无需 Node/NPM。

正式入口 `启动医疗系统.bat` / `start.bat`，默认 5000；演示入口 `启动V2演示系统.bat`，默认 5050。首次安装需要联网；安装后相同依赖指纹不重复安装。

## 二、300 位完整虚构案例

`seed_demo_v2.py` 使用固定随机种子及截至 2026-11-26 的日期。`--replace` 显式覆盖并先留恢复备份；不加该参数拒绝覆盖普通已有库，当前同版本案例库保留修改。演示入口的 `--upgrade-demo` 只将旧版标记演示库升级一次。生成过程先在临时目录完成，验证完整性及外键后才替换目标库。

| 健康评估 | 600（每人 2 份） |
| 完成服务 | 3,948（3,794 次六项目服务、154 次非设备上门） |

| 体验/阶段评价 | 3,343（2,683 单次、660 阶段窗口） |

| 检测报告记录 | 1,111 |
| 个人指标记录 | 8,100（300 人 × 9 类指标 × 3 个日期） |

| 维修记录 / 虚构设备 / 排班窗口 | 18 / 12 / 3,384 |

每个月均有六项目服务、阶段复评、上门记录；不同项目有不同服务量及反馈分布。包含未评价、不适用、加重、未复评、待处理意见和未恢复故障，以便体验跟进功能。没有未知年龄或性别，系统不会为了演示将空缺检测当成正常。排程避开设备停机窗口，同一设备及同一干部的完成服务不存在时间重叠。

默认年度指标：300 人、3,948 服务人次；康养应评价 2,627 次、有效评价 2,474 条、改善 1,908 条，改善率 77.1%、覆盖率 94.2%；总体满意有效 849 份、满意 687 份、满意率 80.9%。修改案例后页面会相应变化。这些都是虚构验证值，不代表实际经营或医学疗效。

随包清单见 [cases-300.json](../cases-300.json)，每次重新生成也会在目标目录写入 `cases_manifest.json`。原始预约表与 V2 服务表分开保存不同服务，没有为填充模块重复生成同一人次。明细表每页 50 行，导出包含完整结果；个人档案自动展示首位干部并可切换或搜索。

## 四、统计口径

- **人群**：建档日期截至期末、未删除的干部；年龄按期末计算；展示五个给定年龄段及男/女，当前 300 位案例均完整。兼容旧库的后端仍保留缺失计数，不凭空指定性别或年龄。项目筛选限定期间使用该项目的人群，个人档案不受群体筛选限制。
- **画像**：截至期末最新健康评估，每人只取一份；病史、症状、检测结论是独立字段，不由病史推断异常。明确“无”为有效回答；未检测、空白、不详不当正常。异常率用对应检测问题有效人数作分母。V2 数值测量用于个人趋势，不擅自转成群体异常诊断。
- **服务量**：六项正式项目及约定的非设备上门，按实际完成时间；人数跨项目去重，人次按完成记录。同一上门记录只计一次。预约按预约日期；履约分母排除取消，期末以后完成的服务不算期内已履约。
- **历史日期**：旧预约没有实际完成时间时，使用原预约结束时间代理，并在运营页和报告注明数量；不伪造完成时间。
- **评价**：改善率 =（明显改善＋部分改善）/（明显改善＋部分改善＋无变化＋加重）。覆盖率 = 有效评价 / 应评价；未评价不进入有效分母，不适用及检测类不进入应评价。旧“无改善”默认值待核验，不自动视为无变化。零分母显示“—”。
- **评价时点**：项目反馈针对所选期间完成服务，使用截至期末已登记的评价；阶段汇总按窗口结束日期，实际复评晚于期末视为未复评。使用次数分组取该服务完成时累计次数，仅表示观察性关联。四象限仅显示有效评价 n≥5 的康养项目。
- **满意度**：按问卷回答日期；总体问题和各维度分母独立；未答不记 0。总体覆盖率为期间服务人群中答过总体问题的人数/服务人数。需求多选按回答该题的**去重人数**计算，而非选项数。项目筛选只纳入明确关联对应服务的问卷。
- **设备时长**：仅按已登记的真实排班窗口和相交停机/服务时段计算，未提供时长分母显示“—”。本版虚构排班覆盖 1–11 月每周一、三、五上午及下午；统计至案例截止日，分母剔除停机重叠时间。维修次数按报告日期，资产状态由维修闭环更新。
- **专业管理**：风险等级与参考范围由获授权专业人员或管理员输入；系统不自动诊断。驻场人员不能改写已确认检测结论及原报告，只能更新跟进。
- **历史可变性**：系统保留业务审计，但不是不可变历史快照仓库。纠错更新当前记录后，重新生成历史期间报告可能变化。正式定稿应保存当时的 PDF/Excel 与数据库备份。

## 五、白名单迁移与保护

| 编码 | 标准名称 | 类型 |
| --- | --- | --- |
| MOXA | 艾灸 | 康养 |
| OXYGEN | 高压氧仓 | 专业服务 |
| HEARING | 听力测试 | 检测筛查 |
| INFRARED | 红外理疗 | 康养 |
| IMMUNO | 荧光免疫分析仪 | 检测筛查 |
| MASSAGE | 按摩机器人 | 康养 |

标准名称直接对应。旧“艾灸机器人”“高压氧舱”“听力检测仪/听力检测”“太空针灸按摩仪”“手持式干式荧光免疫分析仪”只生成建议映射，**不会自动认定同义**。管理员核实后通过管理页面确认，保存确认人和时间；映射不重写历史服务原项目编号。

其他设备项目的原主数据写入 `v2_archive.original_json`，正式入口中停用；历史业务仍可在原查询、附件和个人档案访问。普通 V2 迁移不物理删除历史业务；本次用户明确要求的案例覆盖由独立 `--replace` 流程执行，不与普通迁移混用。迁移比较客户、评估、现场/上门预约、改善记录前后总数，记录 `v2_migrations`。设备主数据根据实际资产映射或登记，重新启动不禁用自定义设备映射。

只读检查实际库（不会启动应用或触发迁移）：

```cmd
python manage_v2.py inspect --data-dir D:\health_agent_data
```

输出完整性、外键错误、表数量、迁移日志、待核验别名。既有库如含历史孤立引用，应根据此输出核实原数据；不通过删除业务记录掩盖错误。

### 回滚步骤

1. 停止全部程序窗口和后台进程，暂停业务登记。准备迁移前备份，核对备份路径。
2. 使用当前版本工具，执行（替换为实际文件名）：

```cmd
python manage_v2.py restore --data-dir D:\health_agent_data --backup D:\health_agent_data\database_backups\before_care_v2_实际时间.db --server-stopped
```

3. 工具先备份当前数据库为 `before_restore_*.db`，再从指定备份恢复，并输出核验结果。不删除附件；不同源/目标和完整性检查用于避免误操作。
4. 使用**该备份对应的旧代码版本**启动。不要用 V2 代码立刻启动恢复后的库，否则会再次迁移。
5. 升级之后录入的记录在 `before_restore_*.db` 中保留，按业务需要单独核对转入；不会自动合并不同版本的写入。

## 六、权限与验证

管理员配置账号；`can_view_personal` 和 `can_export` 分别控制个人访问和报告导出。管理人员无个人授权时不返回姓名、个人记录列表或原始反馈文本，人数不足 5 的筛选不提供细分统计。个人端所有读取校验绑定的干部编号，不能通过修改 URL 或直接调用旧接口查看他人。停用账号即时使会话失效。

回归测试覆盖启动、原业务 API、Excel、备份、密钥持久化、中文/传统 Windows 控制台、端口冲突、六项目录、历史归档及确认、人数人次、有效分母、日期边界、配对缺失、阶段去重、维修台账、角色隔离、专业结论保护及导出一致性。GitHub Actions 同时运行 Windows Python 3.10/3.12/3.14 与 Ubuntu 3.12，并验证 Windows `start.bat --install-only`。

浏览器检查使用 Chromium：六页桌面与 390px 手机布局，运营六板块，预约→基线→完成→反馈，指标登记，复评，问卷→任务闭环，维修→恢复，四类 PDF/Excel，以及个人端越权拦截。

300 案例专项验证覆盖所有模块非空且有差异的图表数据、干部与设备排程不重叠、阶段评价关联实际服务、年龄性别 Excel 五行、覆盖删除旧档案及恢复备份、普通启动不重置数据。
